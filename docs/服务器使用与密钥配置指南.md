本文档面向**已经部署到阿里云 ECS 的 FinScope AI**，回答四个问题：怎么登录和操作、里面有哪些数据、模型密钥怎么配、日常怎么维护。
通用功能说明见 `docs/使用说明.md`；本文只补充服务器环境下的具体操作。

> 本系统只用于研究与学习，不构成投资建议，也不提供交易执行。

### 2.1 看一家公司的数据（最常用）

1. 登录后在顶部搜索框输入代码或中文名，例如 `600519`、`茅台`、`AAPL`。
2. 打开公司页。如果这家公司还没有抓过数据，页面会显示「正在同步」，系统已登记后台抓取任务，**等 1 到 2 分钟刷新**即可。失败后有 15 分钟冷却，避免反复触发。
3. 点「加入自选」。自选里的公司会被定时任务**每天自动刷新**，没加入自选的公司只在你打开时按需抓取。

### 2.2 数据为空时先看哪里

1. 打开「系统设置 → 运行状态」，按「正常 / 过期 / 缺失 / 不可用」逐项看，缺哪项一目了然。
2. 页面写「不可用」通常是**没配对应密钥**（见第 4 章），写「缺失」是**还没抓**，写「过期」是**抓过但很久没更新**。
3. 系统对缺数据的处理原则是：**如实显示空或不可用，不用假数字填充**。所以页面空比页面有假数据更符合设计。

### 3.1 为什么有些数据「看不到」——时间旅行规则

系统遵守「不使用未来数据」：只有**发布时间不晚于查看日期**的数据才会显示。这会造成两种看起来像「空」的情况：

- **美国宏观，没有 FRED 密钥时**：公开 CSV 不带历史发布日期，系统只能把「首次抓到的那天」当作发布日，并规定**发布日当天不可见，次日才可见**。所以第一天抓的数据，要到第二天（纽约时间日期变更后，约北京时间中午 12:00）才出现。配置 FRED 密钥后，每条数据带真实发布日，历史数据当天可见。
- **中国宏观**：公开接口不提供真实发布日，系统把每期的可见日定在**偏晚的保守上界**（CPI、PPI 次月 15 日，PMI 次月 1 日，M2、工业增加值、社融次月 20 日）。宁可晚几天出现，也不提前使用未公布的数据。这是有意设计，不是故障。

### 3.2 不会有的数据

- 没有实时行情；所有行情页面都不写「实时」。
- 没有新闻、舆情；热点只统计官方披露条数，不含情绪判断（`ENABLE_NEWS` 只读已入库的官方披露）。
- 没有 Tiingo 密钥时没有美股日线；没有模型密钥时 AI 问答和研究报告里的 AI 段落不可用。

## 4. 密钥怎么配置

所有密钥都由**管理员在网页里填写**，加密保存在数据库，保存后几秒内对 api、worker、scheduler 同时生效，**不需要重启**。

### 4.1 操作步骤

1. 用 `admin` 登录。
2. 左侧点「数据管理」→ 找到「密钥与数据源配置」面板（只有管理员能看到）。
3. 在对应项里粘贴密钥，点**保存**。保存后界面只显示掩码，例如 `••••a1b2`，完整内容不会再被任何接口返回，也不会写进日志。
4. 点**测试连接**，系统会用该值真的请求一次对应服务，告诉你通不通。测试不会回显密钥。
5. 去掉一个密钥：点**清除**，会退回服务器 `.env` 里的值（`.env` 里没有就是未配置）。

界面里保存的值**优先于** `.env`。

### 4.2 可以在界面配置的项目

| 配置项 | 用途 | 没填会怎样 | 获取地址 |
|---|---|---|---|
| `SEC_USER_AGENT` | 访问 SEC EDGAR 的身份标识，必须含联系邮箱 | 美股财报、披露可能被 SEC 限流或拒绝 | 不用申请，自己写 |
| `FRED_API_KEY` | 美国宏观，带历史发布日的时点数据 | 退回公开 CSV，只有最新修订值，且首日不可见（见 3.1） | https://fred.stlouisfed.org/docs/api/api_key.html |
| `TIINGO_API_KEY` | 美股日线行情 | 美股日线显示「不可用」 | https://www.tiingo.com/account/api/token |
| `LLM_API_BASE_URL` | 大模型接口地址（OpenAI 兼容） | AI 功能显示「模型不可用」 | 见 4.4 |
| `LLM_API_KEY` | 大模型密钥 | 同上 | 见 4.4 |
| `LLM_MODEL` | 模型名称 | 同上 | 见 4.4 |
| 开放注册 | 登录页是否显示注册入口 | 当前服务器默认关闭 | 界面开关 |

### 4.3 各项的填写要点

**SEC_USER_AGENT**（建议第一个改）
格式：`名称 邮箱`，例如 `FinScopeAI yourname@163.com`。必须含 `@`，否则保存会被拒绝。现在的默认值是占位的 `research-admin@example.com`，请改成你自己的真实邮箱。点测试连接，通过说明 SEC 接受。

**FRED_API_KEY**
注册 FRED 账号后在「API Keys」里申请，是 32 位小写字母加数字，免费。填入后点测试连接。填好后需要**重新同步一次**美国宏观，历史数据才会带上真实发布日（让运维重新触发，或等 scheduler 下一次每日任务）。

**TIINGO_API_KEY**
注册 Tiingo 免费账号，在 Account → API 里复制 Token。免费档限额很小（约每小时 50 次、每天 1000 次），系统每轮最多只刷新 `SCHEDULER_US_BARS_MAX_SYMBOLS`（默认 30）家，不会一次抓完。

### 4.4 模型密钥（LLM）怎么配

系统使用 **OpenAI 兼容接口**：只要服务商提供 `/chat/completions` 与 `/models` 这样的接口就可以接入。需要填**三项**，缺一项都视为未配置：

| 项 | 含义 | 示例 |
|---|---|---|
| `LLM_API_BASE_URL` | 接口根地址，**不带** `/chat/completions` | `https://api.deepseek.com/v1` |
| `LLM_API_KEY` | 服务商给的密钥 | `sk-...` |
| `LLM_MODEL` | 模型名称，必须和服务商文档一致 | `deepseek-chat` |

**重要：这台服务器在中国大陆（杭州），访问 `api.openai.com` 通常不通。** 请优先选国内可直连的 OpenAI 兼容服务。下面是常见的几家（接口地址和模型名以各家官方文档为准，会变化）：

| 服务商 | `LLM_API_BASE_URL` | `LLM_MODEL` 示例 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里云百炼（通义千问） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 AI | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 月之暗面 Moonshot | `https://api.moonshot.cn/v1` | 以官方文档为准 |
| OpenAI（需服务器能出海） | `https://api.openai.com/v1` | `gpt-4o-mini` |

操作顺序：

1. 在服务商控制台开通并创建 API Key，注意充值或确认免费额度。
2. 到「数据管理 → 密钥与数据源配置」，依次填 `LLM_API_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，每项点保存。
3. 对 `LLM_API_KEY` 点**测试连接**。测试会请求 `{接口地址}/models`：
   - 「模型接口可以访问」：通了。
   - 「模型接口拒绝了这个密钥」：密钥错、没开通或额度用完。
   - 「无法连接到对方服务器」或超时：服务器网络到不了该地址，换一家国内服务商。
   - 个别服务商没有 `/models` 接口，测试会报 HTTP 404 之类；这**不一定**代表对话接口不能用，可以直接去 AI 投研助手发一个问题验证。
4. 验证：浏览器访问 `http://121.199.8.235/api/v1/analysis/model-status`，或在「AI 投研助手」里提问。状态会如实写出模型是否已配置，没配置时系统走规则分支，**不会用固定话术冒充 AI 回答**。

模型被用在哪：AI 投研助手问答、研究报告里的 AI 解读段落、研究推演里的模型节点。数字都由后端按已披露事实计算，模型只负责组织文字；回答带来源，资料不足时会说「证据不足」。每日有 token 预算上限（`AI_DAILY_TOKEN_BUDGET`，默认 200000）。

### 4.5 密钥安全须知

- 密钥**只填在管理员页面**或服务器 `.env`，不要发聊天、不要提交 git、不要截图外传。
- 加密主密钥是服务器 `.env` 里的 `SETTINGS_ENCRYPTION_KEY`。**不要更换它**（也不要更换 `JWT_SECRET`），否则库里已加密的密钥无法解密，会显示成「未配置」，需要重新填写。
- 向量嵌入不需要配置：文档检索使用本地嵌入，`EMBEDDING_*` 保持为空即可。
- `TUSHARE_TOKEN` 只能写在服务器 `.env`，界面里没有这一项；不填不影响核心功能。

### 4.6 也可以直接写 `.env`

不想用网页时，登录服务器编辑 `/opt/finscope/.env`，加入例如：

```
LLM_API_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-xxxx
LLM_MODEL=deepseek-chat
FRED_API_KEY=xxxx
TIINGO_API_KEY=xxxx
```

然后重启后端容器让它读到新值（见 5.2）。**界面里保存过的值会盖过 `.env`**，两处不一致时以界面为准。

## 5. 日常维护

### 5.1 登录服务器

在自己电脑的 PowerShell 里：

```powershell
ssh -i $env:USERPROFILE\.ssh\finscope_admin root@121.199.8.235
cd /opt/finscope
alias fc='docker compose -f docker-compose.prod.yml --env-file .env --env-file .release.env'
```

> 已经在服务器里面时（提示符是 `root@iZ...`），**不要再执行 `ssh ...`**，直接运行 `fc ...` 命令。`$env:USERPROFILE` 是 Windows 写法，在服务器上不存在。

### 5.2 常用命令（在服务器 `/opt/finscope` 里）

| 用途 | 命令 |
|---|---|
| 看容器状态 | `fc ps` |
| 看日志 | `fc logs -f --tail=100 api worker scheduler` |
| 重启后端三个进程 | `fc restart api worker scheduler` |
| 灌入初始数据（幂等） | `fc exec -d api sh -c "python -m app.scripts.bootstrap_data > /tmp/bootstrap.log 2>&1"` |
| 看灌数据进度 | `fc exec api tail -f /tmp/bootstrap.log`（`Ctrl+C` 退出，不会中断任务） |
| 进数据库 | `fc exec db psql -U finscope -d finscope` |
| 备份数据库 | `fc exec -T db pg_dump -U finscope finscope > ~/finscope-backup-$(date +%F).sql` |
| 看当前部署版本 | `cat .release.env` |

日志里不会出现密钥和密码。备份文件里含账号哈希和加密后的密钥，**不要提交仓库、不要外传**。

### 5.3 手动抓取某类数据

不用等定时任务时：

- **网页方式**：管理员进「数据管理」，手动触发同步并看任务状态。
- **命令方式**（例如重新抓中国宏观）：

```bash
fc exec -T api python - <<'PY'
import asyncio
from app.core.config import get_settings
from app.db.session import create_db_engine
from app.services.data_sync import sync_china_macro
engine = create_db_engine(get_settings().database_url)
print("写入条数:", asyncio.run(sync_china_macro(engine)))
PY
```

抓取全部有限速、重试、超时，并且幂等：重复触发不会产生重复数据。

scheduler 只负责**登记**任务，worker 负责**执行**，两个都在运行数据才会自动更新。时区为 `Asia/Shanghai`。

| 中国宏观六序列 | 每日 01:20 | 其余任务时间见 `.env.example` 中 `SCHEDULER_*` |
| A 股日线 | 每个交易日收盘后 | 只更新自选 / 被关注的 |
| A 股财报、美股财报 | 每日 | |
| 美国宏观（FRED） | 每日 | |
| 证券清单 | 每周 | |
| 财务体检快照、宏观状态快照 | 每日 | 体检只算有真实披露的公司 |

## 6. 自动部署怎么工作

代码合并到 `master` 且 `ci` 工作流通过后，GitHub Actions 的 `deploy` 工作流会自动：

1. 在 GitHub 的构建机上构建后端、前端镜像，标签是提交的前 12 位。
2. 经 SSH 把镜像传到服务器（服务器不用访问 Docker Hub、GitHub、PyPI）。
3. 执行 `/opt/finscope/deploy.sh`：启动新版本、探测 `/api/v1/health/live`。
4. **探测失败会自动回滚到上一个版本。**

需要的 GitHub 仓库 Secrets：`DEPLOY_HOST`、`DEPLOY_USER`、`DEPLOY_SSH_KEY`、`DEPLOY_KNOWN_HOSTS`。

手动重新部署：GitHub 仓库 → Actions → `deploy` → Run workflow。数据库迁移在 api 容器启动时自动执行。

数据和密钥都在服务器的 Docker 卷与 `.env` 里，**部署新版本不会清空数据**。

## 7. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面能打开但全是空的 | 新库未灌数据：见 5.2 灌入初始数据，或打开公司页触发按需抓取 |
| 美国宏观页是空的，库里有数据 | 时间旅行规则，首日不可见，次日可见；填 FRED 密钥可避免，见 3.1 |
| 中国宏观是空的 | 新服务器未跑过 01:20 的任务：见 5.3 手动抓取 |
| 宏观情景分析显示「数据不足」 | 美国或中国序列还没有可见数据，如实显示不足，数据可见后下一次每日任务自动算出 |
| 美股日线不可用 | 没填 Tiingo 密钥，或当日免费额度用完 |
| AI 助手显示模型不可用 | 三项模型配置没填全，或服务器访问不到该接口地址，见 4.4 |
| 公司页一直「正在同步」 | worker 没运行，或上游限流；看「运行状态」页该任务的失败次数与原因 |
| 登录一段时间后掉线 | 检查服务器 `.env` 里是否有 `COOKIE_SECURE=false`（HTTP 部署必须有） |
| 密钥突然变成「未配置」 | 更换过 `SETTINGS_ENCRYPTION_KEY` 或 `JWT_SECRET`，需重新填写 |
| `/api/v1/health/ready` 返回 503 | worker 还没上报心跳，系统会如实写原因 |
| 研究员打开「数据管理」是 403 | 只有管理员能进，研究员账号没有权限 |
| 网站打不开 | 检查阿里云安全组是否放行入方向 TCP 80，并 `fc ps` 看容器状态 |

## 8. 已知局限

- 当前是 HTTP 部署，没有域名与 HTTPS。
- 数据库没有自动备份，需要自行定期执行 5.2 的备份命令，或在阿里云开磁盘快照。
- 服务器内存只有 3.6 GB，同时运行数据库、api、worker、scheduler，大批量任务并发时可能偏紧。
- 美股日线、AI 功能依赖你自己的第三方密钥，质量与额度由服务商决定；系统保证数字来自后端、来源可追溯，不保证结论正确。
- 中国宏观的发布日是保守上界，不是官方真实发布日。
