# 部署、演示、许可和局限

本文档记录**本机（Windows，非管理员账号）实际验证通过**的部署方式，以及演示顺序、数据许可与已知局限。
文中所有端口、账号和路径都与实际运行的实例一致。

## 一、部署形态

规格书的技术选型里部署是 Docker Compose + Nginx。本机**没有采用 Docker**，原因是这台机器上的账号不是管理员，
装不了 Docker Desktop、也用不了 WSL 与 Windows 服务注册。因此改用同一套组件的**原生 Windows 进程**部署：

| 规格书组件 | 本机实现 | 位置 |
| --- | --- | --- |
| PostgreSQL + pgvector | PostgreSQL 16.2 + pgvector 0.6.2 解压式运行 | `C:\finscope-runtime\pgsql`、数据目录 `C:\finscope-runtime\pgdata` |
| FastAPI（api） | uvicorn 直接跑 `app.main:app` | `http://127.0.0.1:8000` |
| 独立 Worker | `python -m app.workers.main` | 同进程组，心跳写入数据库 |
| Nginx（前端） | `vite preview` 托管 `frontend/dist`，用同样的 `/api` 反代规则 | `http://127.0.0.1:8080` |
| 数据库迁移 | Alembic，`alembic upgrade head` | 16 个 revision，落库 `alembic_version` |
| 依赖管理 | `uv sync --extra dev`（Python 3.12.15） | `backend\.venv` |

**为什么数据库运行时不在项目目录里**：`backend` 所在的项目路径含中文（`毕设tl`），
而 Windows 上的 PostgreSQL 16 用 ANSI 代码页解析数据目录，`initdb` 会以
`FATAL: invalid byte sequence for encoding "UTF8": 0xb1` 失败并自动删除数据目录。
因此**数据与二进制固定放在纯 ASCII 路径 `C:\finscope-runtime`**，源代码仍保留在项目目录内。

### 一键启动

```
finscope-ai\windows-deploy\start.bat      # 启动数据库 + API + Worker + 前端，并打开浏览器
finscope-ai\windows-deploy\stop.bat       # 停止全部服务（数据保留）
finscope-ai\windows-deploy\status.bat     # 查看端口、PID、就绪检查、前端地址
```

`start.ps1` 按顺序做四件事，每件都可单独观察结果：
① 若 5432 未监听则用 `pg_ctl` 起库；② 在 `backend` 目录跑 `alembic upgrade head`；
③ 起 uvicorn 与 worker，轮询 `/api/v1/health/live` 与 `/api/v1/health/ready`；
④ 按 `prod`（默认，`vite preview` 8080）或 `dev`（`vite dev` 5173）起前端，最后打印地址与账号。
冷启动实测约 8.5 秒返回。

### 访问地址与账号

| 项目 | 值 |
| --- | --- |
| 前端页面 | `http://127.0.0.1:8080` |
| 接口文档 | `http://127.0.0.1:8000/docs` |
| 存活检查 | `http://127.0.0.1:8000/api/v1/health/live` |
| 就绪检查 | `http://127.0.0.1:8000/api/v1/health/ready`（同时校验数据库与 worker 心跳） |
| 登录账号 | `admin` / `FsScope!2026` |
| 日志 | `C:\finscope-runtime\logs\`（`postgres.log`、`api.*.log`、`worker.*.log`、`web.*.log`） |

`admin` 是开发库口令，只用于本机演示与答辩，**不得用于生产**。

### Docker 路线（本机未使用，仅作可移植性说明）

仓库保留了 `docker-compose.yml` 与 `frontend/nginx.conf`，在有 Docker 的机器上仍是
`docker compose up --build -d`，用 `FINSCOPE_DB_PORT` / `FINSCOPE_API_PORT` / `FINSCOPE_WEB_PORT`
改端口。本机因为端口 5432/8000 未被占用、且无 Docker，走的是上面的原生路线。

## 二、演示顺序

1. 打开 `http://127.0.0.1:8080`，先看运行状态页：数据库与任务服务是否就绪、当前数据时间。
2. 美国宏观：序列目录按 FRED 定义展示；**没有 `FRED_API_KEY` 时数值一律显示不可用**，不补数。
3. 指数行情 / 股票行情：`600519.SH`、`601318.SH`、`000858.SZ` 等已入库真实日线，
   可直接看 K 线与均线；没有 K 线的日期不补零。
4. 公司研究：SEC 样例对比 2022-12-31 与 2023-12-31，**80 和 120 是本地夹具数字，不是苹果真实收入**。
5. 研究报告：保存研究记录后打开，核对申报号与引用页码。
6. 上传：传一份文字版 PDF，用原文检索定位页码；非 PDF、超 30MB、超 200 页会被明确拒绝。
7. 产业研究：用 120 作为支持、50 shares 作为反证，假设状态为 `contested`。
8. 市场温度 / 板块排行：成分或样本不足时明确写「无法判断」，不给分数。
9. 市场热点：公告类事件按来源白名单与去重键入库；没有合规公告时显示空状态而不是情绪分数。
10. 中国宏观：6 条官方序列在导入带来源的 CSV 之前保持不可用。
11. 研究推演：用 `600519.SH`，2026-06-01 看不到中报、2026-08-16 看得到，评级不是下单指令。

## 三、数据许可

- **美国宏观**来自 FRED，需要 `FRED_API_KEY`，遵守 FRED 使用条款；本机未配置密钥，序列不可用。
- **美股事实样例**来自 SEC `companyfacts` 的本地夹具（`backend/app/providers/fixtures/sec_companyfacts.json`），仅用于走通链路。
- **A 股日线**经东方财富公开行情接口抓取，只保存公开行情字段；页面一律不称「实时」。
- **茅台两期累计收入与披露日**写在规格书 21.4，只用于 Mock 回放。
- **巨潮、交易所公告**只保存标题、时间与链接，不转载全文。
- **PostgreSQL 16.2 与 pgvector 0.6.2** 由 PyPI 上的 `pgserver` 二进制发行包提供，
  分别是 PostgreSQL License 与 PostgreSQL License（pgvector 采用同一许可），仅本机开发使用。
- **TradingAgents** 上游协议为 Apache-2.0，依赖钉在提交 `1394a3f72aa4393e1a98f51b382434c4b4c2d972`；
  推演调用已安装包里的 `TradingAgentsGraph.propagate`，模型用 Mock，不读取 StockTwits 或 Reddit。

## 四、局限与如实声明

- **没有配置外部语言模型与向量模型**（`LLM_*` / `EMBEDDING_*` 为空）。
  报告与问答会明确走规则分支，不伪造 AI 结论；`/api/v1/analysis/model-status` 会如实报告模型未配置。
- **美股行情与宏观数值缺失**：没有 FRED 密钥、没有付费行情源，相关页面显示不可用。
- **中国宏观缺失**：没有 TUSHARE_TOKEN 或官方 CSV 时，6 条序列保持不可用。
- **行业目录**目前只有信息技术与苹果样例。
- **报告导出**用浏览器打印，未在服务端单独安装中文排版引擎。
- **推演没有委托接口**，区间收益只在已入库收盘价足够时写入，不足时页面写「样本不足」。
- **市场温度、板块、社融**在样本或正式文件不足时，一律写「无法判断」或「不可用」，不用假数据填充。

## 五、演示前自检

```powershell
# 1. 服务状态
finscope-ai\windows-deploy\status.bat

# 2. 后端质量门（ruff + format + mypy + pytest）
cd finscope-ai\backend
.\.venv\Scripts\python.exe -m pytest -q

# 3. 前端质量门（vitest + 类型检查）
cd ..\frontend
npm test
npm run typecheck
```

三项全绿再演示。任何一项失败，先修再演，不要用「演示环境特殊」解释。
