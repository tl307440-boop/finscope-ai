# FinScope AI 使用说明

本文档面向三类读者：**使用者**（研究员）、**管理员**（填密钥、管账号、看数据状态）、**部署者**（把系统放到服务器上）。
FinScope AI 是个人投研辅助系统，只用于研究与学习，不构成投资建议，也不提供交易执行或收益承诺。

> 阅读顺序建议：先看第 1、2 章把系统跑起来，再按角色看后面的章节。遇到报错看第 12 章。

---

## 1. 系统由哪几部分组成

| 组成 | 作用 | 对应容器 |
|---|---|---|
| 前端 | 浏览器里看到的所有页面 | `frontend`（默认 <http://localhost:8080>） |
| API | 登录、查询、发起分析、管理配置 | `api`（默认 <http://localhost:8000>，接口文档 `/docs`） |
| worker | 真正去抓数据、解析 PDF、算指标的后台执行者 | `worker` |
| scheduler | 每天按时间表「登记」要做的任务，交给 worker 执行 | `scheduler` |
| 数据库 | PostgreSQL（带 pgvector），所有数据都在这里 | `db` |

三点需要记住：

1. **scheduler 只登记，不执行；worker 才执行。** 两个都在运行，数据才会自动更新。
2. api、worker、scheduler 是三个独立进程，它们读同一个数据库。所以在界面里保存的密钥，几秒内就对三个进程同时生效，不用重启。
3. 页面上的金额、比例、增速全部由后端按已披露的事实计算，前端只负责展示。AI 的回答不会直接给数字，数字来自后端工具。

## 2. 快速开始（本机）

需要：Docker、Python 3.12、Node.js 22（Windows 直接用 PowerShell）。

```powershell
cd backend
uv sync --extra dev
cd ../frontend
npm ci
cd ..
docker compose up --build -d
```

打开 <http://localhost:8080>。端口被占用时可以改：

```powershell
$env:FINSCOPE_DB_PORT = "54329"
$env:FINSCOPE_API_PORT = "18000"
$env:FINSCOPE_WEB_PORT = "8080"
docker compose up --build -d
```

首次启动时数据库是空的：证券清单、财报、行情会由 scheduler 和 worker 在后台陆续抓取，也可以在打开某家公司页面时按需触发（见第 7 章）。想一次性灌入一批初始数据，可以运行：

```powershell
cd backend
uv run python -m app.scripts.bootstrap_data
```

## 3. 账号：注册、登录、改密码

### 3.1 第一个管理员怎么来

有三种方式，任选其一：

1. **环境变量自动创建（推荐，适合服务器）**：启动前设置 `ADMIN_USERNAME`、`ADMIN_EMAIL`、`ADMIN_PASSWORD`。API 启动时如果发现这个账号不存在，会自动创建为管理员；已存在则什么都不做，不会覆盖已有账号的密码；密码不满足强度要求时会在日志里告警并跳过。
2. **命令行**：同样设置上面三个环境变量后运行 `cd backend && uv run python -m app.scripts.seed`。
3. **数据库里已有管理员**：比如你之前在本机建过的账号，沿用即可。

### 3.2 自助注册

登录页有「注册新账号」入口：

- 账号名 3–30 位，只能用字母、数字、下划线、点、短横线；系统统一转成小写，登录时不区分大小写。
- 密码至少 8 位，需要同时包含字母和数字，不能是常见弱密码，也不能和账号名相同。
- **自助注册出来的永远是「研究员」**，不能自己变成管理员。管理员只能由环境变量、命令行或数据库产生。
- 同一个 IP 每小时最多注册 5 次（`REGISTER_MAX_PER_HOUR`）。
- 注册成功后自动登录。
- 不想开放注册：管理员在「数据管理 → 密钥与数据源配置」里把「开放注册」关掉（立即生效），或者设置环境变量 `ALLOW_REGISTRATION=false`。关闭后登录页不再显示注册入口，接口也会拒绝注册。

### 3.3 修改密码

「系统设置 → 修改密码」。修改成功后，**其它设备上的登录会立即失效**，当前设备保持登录。

### 3.4 角色能做什么

| 能力 | 研究员 | 管理员 |
|---|---|---|
| 看宏观、行情、公司、行业、热点 | ✔ | ✔ |
| 发起 AI 分析、问答、上传 PDF、管自选 | ✔ | ✔ |
| 打开「数据管理」、填密钥、手动同步、看数据源状态 | ✘（403） | ✔ |

## 4. 管理员：在界面里填密钥

> 路径：左侧「数据管理」→「密钥与数据源配置」。只有管理员能看到这个页面。

### 4.1 可以在界面管理哪些项

| 配置项 | 用途 | 没填会怎样 |
|---|---|---|
| `TIINGO_API_KEY` | 美股日线行情 | 美股日线显示「不可用」，不会造数据 |
| `FRED_API_KEY` | 美国宏观序列（FRED） | 回退到 FRED 公开 CSV，序列覆盖有限 |
| `SEC_USER_AGENT` | 访问 SEC EDGAR 的身份标识（SEC 要求带联系邮箱） | 美股财报、美股披露无法抓取 |
| `LLM_API_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | AI 助手、研究报告、推演里的模型调用 | AI 功能显示「模型不可用」，不会用固定话术冒充回答 |
| 开放注册 | 登录页是否允许注册 | — |

### 4.2 每一项的操作

- **保存**：输入后点保存。密钥**加密存进数据库**，之后界面只显示掩码（形如 `••••a1b2`），完整内容任何接口都不会再返回，也不会进日志。
- **测试连接**：用刚保存的值真的去请求一次对应服务，告诉你通不通。测试不会回显密钥。
- **清除**：删除界面里保存的值，退回环境变量里的值（环境变量也没有就是未配置）。
- **优先级**：界面里保存的值 **高于** 环境变量；环境变量只是初始默认值。
- **生效时间**：最多几秒（有短缓存），api、worker、scheduler 同时生效，不需要重启。

### 4.3 加密主密钥

加密用的主密钥取自环境变量 `SETTINGS_ENCRYPTION_KEY`；留空时用 `JWT_SECRET` 派生。

> ⚠️ **更换主密钥（或更换 `JWT_SECRET`）后，库里已加密的密钥将无法解密**，对应配置会被当作「未配置」，需要管理员重新填写。所以：生产环境请**一次性**设置好长随机串，之后不要再改；并确保 api / worker / scheduler 三个服务使用同一个值（`docker-compose.yml` 已经把它们统一从同一个环境变量读取）。

### 4.4 也可以继续用 `.env`

不想用界面时，把密钥写进 `.env` 照样可用（复制 `.env.example` 为 `.env` 再改）。**`.env` 已被 git 忽略，永远不要提交到仓库。**

## 5. 功能页面导览

左侧导航共 12 个一级入口（11 个是规格书的，「自定义数据分析」是后加的）：

| 入口 | 内容 |
|---|---|
| 总览驾驶舱 | 市场与宏观的一屏概览；二级有「研究板」「研究推演」 |
| 全球宏观 | 美国经济、中国宏观、货币流动性、宏观情景分析（见第 6 章） |
| 市场行情 | 指数、板块排行、个股行情、市场温度 |
| 公司研究 | 单家公司的财务卡片、财报对比、体检指标、披露文件、上传资料 |
| 产业研究 | 申万一级行业总览、行业详情、逻辑追踪 |
| 市场热点 | 近期官方披露按类型聚合（只统计条数，不含情绪判断） |
| AI 投研助手 | 基于后端工具和已披露数据的问答 |
| 自定义数据分析 | 四大宽基与科创50 期权 PCR、股债收益差、巴菲特指标、全市场中位数 PB（见 5.6） |
| 研究报告 | 已生成的分析报告库 |
| 自选关注 | 你关注的公司（也决定哪些公司会被定时刷新） |
| 数据管理（仅管理员） | 数据源状态、手动同步、密钥与数据源配置 |
| 系统设置 | 主题、偏好、修改密码；二级有「运行状态」 |

### 5.1 公司研究

- 搜索框支持代码与中文名，覆盖 A 股和美股（Nasdaq / NYSE）全市场清单。
- 首次打开一家还没有数据的公司（需要登录），系统会**登记后台抓取**并显示「正在同步」，抓完刷新即可；已在队列里的不会重复登记。
- 财务卡片对比的是**同口径**数据（同一科目、同样的期间长度、同比用约一年前的同期），对不上口径就显示「—」，不会硬凑。
- 美股外国发行人（如 TSM、NVO，披露 20-F / 40-F / 6-K）的财报采用 IFRS，金额的**币种是它的报告币种**（新台币、丹麦克朗等），界面会写明币种，系统不做汇率换算。
- 数据状态有四种：真实披露（`edgar` / `eastmoney`）、样例（`sample`，仅演示）、空（`empty`）。**样例数据会明确标注，不会冒充真实数据。**

### 5.2 财务体检快照

调度任务每天为「被关注」的公司（自选、已有财报或行情的 A 股与美股）计算一组指标，存进数据库：

营收同比、净利润同比、毛利率、资产负债率、流动比率、经营现金流 / 净利润。

- 只用真实披露的事实；一家公司没有任何真实披露就什么都不写。
- 每个指标都带取数来源（科目、申报单号、来源链接）。
- 算不出来的存空并写明原因，例如「缺少去年同期同口径事实」「净利润不为正，现金含量没有意义」「基期为负，不计算增速」。
- 接口：`GET /api/v1/companies/{id}/metrics?as_of=YYYY-MM-DD`；`as_of` 之前尚未披露的快照不可见（时间旅行）。

### 5.3 AI 投研助手与研究报告

- 需要先配置 LLM（第 4 章）；没配置时如实显示不可用。
- 回答里的数字由后端工具给出，来源写在回答里；资料不足时它会说「证据不足」，而不是编。
- 每次分析会存成一份报告，可以在「研究报告」里回看。

### 5.4 上传 PDF

公司页的「上传」入口可以上传财报等 PDF（单个默认最多 30 MB、200 页）。解析由 worker 异步完成，解析有时间预算，超时会标记失败而不是卡住。上传的文件属于用户数据，不进 git。

### 5.5 研究推演

「总览驾驶舱 → 研究推演」是沙盘：用历史数据做假设推演，默认只读已披露的数据，不构成收益承诺。

### 5.6 自定义数据分析

侧栏「AI 投研助手」下面。三个分组，用地址里的 `?tab=pcr|valuation|sources` 记住当前位置：

- **期权 PCR**：上证50、沪深300、中证500、中证1000、科创50 各一页。ETF 期权与中金所股指期权**分开**展示（不是同一种合约，不混算）；中证1000 没有 ETF 期权，只有中金所 MO；科创50 只有上交所的两只 ETF 期权（华夏 588000 + 易方达 588080，加总后再算 PCR），中金所暂时没有科创50 股指期权，所以只有一张卡。每个篮子给成交量 PCR、10 日均线、持仓量 PCR、5 年分位、信号，以及跟踪指数收盘的叠加曲线，可以导出 CSV。
  - 信号有两种：固定阈值（成交量 PCR > 1.2 极度恐慌、< 0.6 极度贪婪，是经验线）和相对信号（自己最近 5 年的分位，≥ 90 偏恐慌、≤ 10 偏贪婪）。**不足 750 个交易日时不给分位**。
- **估值水位**：股债收益差 ERP（带 ±2σ 通道）、巴菲特指标（A 股总市值 / 滚动 4 季 GDP）、全市场中位数 PB（同时画「不剔除 ST」的对照线）。缺输入的指标整张卡写明原因，不用估算值补。
- **数据源与质量**：每个来源的最新日期、行数、待审行数，以及最近被质量闸门标记的数据。

首次使用需要回填历史（见 7.3）。口径、阈值、质量闸门的完整说明见 `docs/superpowers/specs/2026-10-18-custom-analysis-design.md`。

## 6. 宏观数据

### 6.1 美国

来自 FRED（带 API Key 用 observations 接口，没有则用公开 CSV）。**时间旅行**：选择一个历史日期，只会看到那一天已经公布的数值和当时的版本（修订会保留历史版本）。

### 6.2 中国宏观六个序列

| 序列 | 来源 | 保守的「公布日」上界 |
|---|---|---|
| CPI 同比 | 东方财富数据中心 | 观察月的**次月 15 日** |
| PPI 同比 | 东方财富数据中心 | 次月 15 日 |
| PMI（制造业） | 东方财富数据中心 | 次月 1 日 |
| M2 同比 | 东方财富数据中心 | 次月 20 日 |
| 工业增加值同比 | 东方财富数据中心 | 次月 20 日 |
| 社会融资规模 | 商务部公开接口 | 次月 20 日 |

**为什么叫「上界」**：这些公开接口不提供真正的发布日期。为了避免「用了当时还没公布的数据」，系统把每个观察月的可见日期定得**偏晚**：宁可晚一点才看到，也不提前泄露未来。因此历史回看时，这些序列可能比官方实际公布日晚几天出现；这是有意的保守处理，不是 bug。

抓取由 scheduler 每天登记一次（`china_macro` 任务），幂等（同一序列同一观察月同一可见日不会重复）。某个来源失败时，其它序列照常入库，任务会按重试策略重来并在状态页标出失败项。

### 6.3 宏观综合判断

规则计算增长、通胀、流动性三项，得出状态标签。**这是规则计算，不是经济定论**；数据不足时给出 `insufficient_data`，不会硬判断。调度任务每天为当天保存一份判断快照，可以通过 `GET /api/v1/macro/regime-history` 回看历史判断。

## 7. 数据是怎么保持更新的

### 7.1 自动更新（scheduler + worker）

| 任务 | 频率 | 说明 |
|---|---|---|
| 美国宏观（FRED） | 每日 | 没有密钥时用公开 CSV |
| A 股日线 | 每个交易日收盘后 | 只更新被关注的 |
| A 股财报 | 每日 | 东方财富 F10 |
| 美股财报 | 每日 | SEC companyfacts（10-K / 10-Q / 20-F / 40-F / 6-K） |
| 美股日线 | 每日，受免费额度限制，每轮最多 `SCHEDULER_US_BARS_MAX_SYMBOLS` 家 | 需要 Tiingo 密钥 |
| 证券清单 | 每周 | A 股用巨潮，美股用 SEC |
| 中国宏观六序列 | 每日 | 见 6.2 |
| 财务体检快照 | 每日 | 见 5.2 |
| 宏观状态快照 | 每日 | 见 6.3 |
| 热点披露刷新 | 每日 | 巨潮资讯 / SEC 官方披露，近 14 天，单次最多 60 家 A 股 + 60 家美股 |
| 文档解析清扫 | 每 5 分钟 | 兜底处理排队中的上传 |
| 自定义数据分析 | 工作日 18:30 | 期权日统计、指数收盘与 PE、国债收益率、GDP、全市场截面；开关 `SCHEDULER_ENABLE_CUSTOM_ANALYSIS`，见 5.6 / 7.3 |

每个任务都有开关，环境变量 `SCHEDULER_ENABLE_*`；总开关 `SCHEDULER_ENABLED`。抓取全部有限速、重试、超时，并且幂等（重复触发不会产生重复数据）。

### 7.2 按需抓取

打开一家数据缺失或已过期的公司时，登录用户会触发后台抓取，失败后有冷却时间（默认 15 分钟）避免被反复刷。

### 7.3 自定义数据分析的首次回填

升级到带 `20261018_0028` 迁移的版本后先 `alembic upgrade head`，然后回填历史（可中断、可重复运行，已入库的交易日不会重抓）：

```bash
cd backend
python -m app.scripts.backfill_custom_analysis                 # 默认 5 年，全市场截面一次补完
python -m app.scripts.backfill_custom_analysis --cross-section-days 200   # 分批补截面
```

- 全市场截面每个交易日要请求十几页，限速下 5 年需要一两个小时；**深交所对连续请求会直接断连**（限流），所以深交所的请求之间多等 3 秒，被封就停，隔一阵再跑一次会接着补。
- 回填没完成时页面不会假装完整：缺深交所数据的 ETF 篮子会显示可用天数很少并标「已过期」。
- 日常由定时任务每个工作日 18:30 增量更新，每次最多补 60 个交易日的全市场截面。

### 7.4 怎么看哪些数据新鲜

「系统设置 → 运行状态」页（或 `GET /api/v1/system/freshness`）按「正常 / 过期 / 缺失 / 不可用」逐项列出：行情、财报、宏观、证券清单、各个同步任务最近一次成功时间、过去 24 小时失败次数、心跳是否在线。**数据缺失、过期会明确显示，不会假装正常。**

## 8. 部署到服务器

### 8.1 最小步骤

1. 在服务器安装 Docker，把代码拉下来。
2. 复制 `.env.example` 为 `.env`，**至少改这些**：

   | 变量 | 说明 |
   |---|---|
   | `JWT_SECRET` | 一个长随机串（32 位以上）。默认值是占位符，**生产绝不能用** |
   | `SETTINGS_ENCRYPTION_KEY` | 另一个长随机串，用于加密库里的密钥。设置后不要再改 |
   | `FINSCOPE_DB_PASSWORD` | 数据库密码，默认的 `change-me` 不能用于公网 |
   | `ADMIN_USERNAME` / `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 首个管理员，见 3.1 |
   | `APP_ENV` | 生产设为 `production`。此模式下系统会**拒绝**占位的 `JWT_SECRET`（或短于 32 位）和含 `change-me` 的数据库口令，启动失败而不是带病运行 |
   | `FRONTEND_ORIGIN` | 前端实际访问地址（浏览器地址栏里那个），用于跨域 |
   | `ALLOW_REGISTRATION` | 公网部署通常建议先 `false`，需要时再在界面开启 |

   生成随机串可以用：`python -c "import secrets; print(secrets.token_urlsafe(48))"`。

3. `docker compose up --build -d`。
4. 用上面设置的管理员账号登录，在「数据管理」里填 Tiingo / FRED / SEC / LLM 的密钥并测试。
5. 建议在前面放一层 HTTPS 反向代理（Nginx / Caddy），不要把数据库端口暴露到公网。

### 8.2 常见问题：我本机的账号和密码，部署到服务器后还能用吗？

**不能直接带过去。** 账号保存在数据库里，而不是代码里：

- `localadmin` 是你本机数据库里的一行记录。服务器上会有一个**全新的空数据库**，里面没有这个账号，所以用它登录服务器会失败。
- 部署时请用 `ADMIN_USERNAME / ADMIN_EMAIL / ADMIN_PASSWORD` 在服务器上**重新创建**管理员，并设置一个**新的强密码**（不要把本机的开发密码带上去）。
- 本机的 `.env`、测试用的 `change-me` 数据库密码、占位的 `JWT_SECRET` 也都不应该用于服务器。
- 如果你确实想把本机的账号一起迁移：用 `pg_dump` 导出、在服务器 `psql` 导入整个数据库（会连同行情、财报一起带过去），然后**务必立刻修改密码**；这种方式不推荐，因为库里还有加密后的密钥——它们只有在服务器的 `SETTINGS_ENCRYPTION_KEY`（或 `JWT_SECRET`）与本机**完全相同**时才能解密。
- 数据库备份文件、`.env`、上传的用户文件都**不要提交到 git**。

### 8.3 升级

`git pull` 后 `docker compose up --build -d`。数据库迁移（Alembic）在 api 容器启动时自动执行，不需要手动操作。

### 8.4 备份

数据库数据在 Docker 卷 `finscope_pg`，上传文件在卷 `finscope_uploads`。定期备份：

```powershell
docker compose exec db pg_dump -U finscope finscope > finscope-backup.sql
```

备份文件里包含用户账号哈希和加密后的密钥，请妥善保管，不要提交仓库。

## 10. 数据来源与使用边界

- 美股财报与披露：SEC EDGAR（公开接口，需要带联系方式的 User-Agent，限速 ≤ 10 次/秒）。
- A 股财报：东方财富 F10 公开页面接口；A 股披露与证券清单：巨潮资讯网。
- 中国宏观：东方财富数据中心、商务部公开接口。
- 自定义数据分析：期权来自上交所、深交所、中金所的官方每日统计；指数收盘与 PE-TTM 来自中证指数公司；10 年国债收益率、GDP、全市场截面来自东方财富数据中心。
- 美国宏观：FRED。美股日线：Tiingo。A 股日线：AKShare。
- 系统**不爬取**需要登录或有明确禁止条款的站点，不绕过任何限制，不使用付费专有数据；新闻类第三方来源默认关闭（`ENABLE_NEWS=false`），热点只统计官方披露。
- 所有结论仅供研究参考，**不是投资建议**。

## 11. 诚实的限制

- 美国日线需要自己申请 Tiingo 免费密钥，免费额度很小，所以每轮只刷新一部分。
- A 股财报的单季度、累计口径取决于东方财富 F10 返回的字段；字段变化时会报 `UPSTREAM_PAYLOAD` 错误，而不是写入错数。
- 20-F / 40-F / 6-K 外国发行人只覆盖已映射的核心科目（营收、成本、毛利、营业利润、净利润、EPS、经营现金流、资产负债等）；公司用了很少见的自定义科目时，对应指标可能为空，界面会标「—」。
- 中国宏观的发布日是保守上界（见 6.2），不是官方真实发布日。
- 自定义数据分析：10 年国债收益率没有与中债网逐日对账；历史日期的 ST 剔除按当前简称近似（页面有「不剔除 ST」对照线）；GDP 用最新修订值；中证1000 的 MO 期权（2022-07 上市）与科创50 ETF 期权（2023-06 上市）上市不足 5 年，样本不够时不给分位。
- 研究报告与 AI 回答依赖你配置的模型，质量和模型有关；系统保证数字来自后端、来源可追溯，不保证结论正确。

## 12. 排错

| 现象 | 原因与处理 |
|---|---|
| 登录提示「账号或密码错误」 | 账号名不区分大小写，但密码区分；连续失败多次会被限流，等几分钟再试 |
| 登录页没有「注册」 | 管理员关闭了开放注册，或 `ALLOW_REGISTRATION=false` |
| 「数据管理」打不开（403） | 当前账号是研究员，需要管理员 |
| 保存了密钥但测试失败 | 看测试结果里的原因：密钥错误、额度用尽、网络不通；系统不会显示密钥本身 |
| 密钥突然「未配置」 | 更换过 `SETTINGS_ENCRYPTION_KEY` / `JWT_SECRET`，库里密文解不开，需要重新填写 |
| 公司页一直「正在同步」 | worker 没运行，或上游限流；看「运行状态」里该任务的失败次数与原因 |
| 美股日线不可用 | 没有 Tiingo 密钥，或额度用完 |
| 页面提示「样例数据」 | 该公司还没有抓到真实披露，系统在展示明确标注的演示样例 |
| 中国宏观某个序列为空 | 看「运行状态」里 `china_macro` 的失败原因；其它序列不受影响 |
| `/health/ready` 返回 503 | worker 还没有上报心跳；系统会说明原因，而不是装作正常 |

查看日志：`docker compose logs -f api worker scheduler`。日志里不会出现密钥和密码。
